## Обязательная часть: 9 баллов

Шаг 4 означает подготовку целей Makefile. Миграции проверяем после добавления
SQL-файлов; запуск из чистого клона — в конце работы.
Конфигурация проверена на 49 случаях отдельным временным скриптом.
HTTP и жизненный цикл проверены на 11 интеграционных сценариях через временный
TCP-прокси к настоящему PostgreSQL. Сам кластер для имитации сбоев не останавливался.
Миграции проверены в отдельной временной БД: ограничения, границы координат,
20 одновременных вставок, повторный up, два down и повторное применение.

- [ ] Структура соответствует заданию; `go build ./...` работает из чистого клона.
- [ ] `make migrate`, `make run`, `make generate` работают; окружение поднимается через `tripgoctl`.
- [ ] Конфигурация из env; обязательные значения проверяются до старта; `.env.example` актуален.
- [x] HTTP-сервер использует `chi`; заданы `ReadTimeout`, `ReadHeaderTimeout`, `WriteTimeout`, `IdleTimeout`.
- [x] `/health`: `200`, JSON `HealthResponse`, без обращения в БД.
- [x] `/ready`: `200` при доступной БД, `503` при недоступной; в обоих случаях JSON `HealthResponse`.
- [ ] `SIGINT` / `SIGTERM`: сервер перестаёт принимать запросы, дожидается текущих, закрывает пул; общий бюджет `SHUTDOWN_TIMEOUT`.
- [ ] Типы и серверные интерфейсы генерируются из OpenAPI; повторная генерация воспроизводима; исходный контракт не изменён.
- [x] Миграции создают `trips`, `trip_status_history`, ограничения и индексы; обе откатываются и применяются повторно.
- [x] Частичный уникальный индекс запрещает две активные поездки одному водителю.
- [x] Пул `pgxpool` настроен через env; при старте выполняется `Ping`.
- [ ] SQL строится `squirrel`, значения параметризованы через `$N`; `23505` нужного ограничения превращается в `driver_busy`.
- [ ] `TxManager.Do(ctx, fn)` открывает транзакцию и передаёт её через контекст.
- [ ] Ошибка или паника в callback вызывает rollback; ошибка или паника передаётся наружу.
- [ ] Вложенный `Do` переиспользует текущую транзакцию; репозиторий вне `Do` использует пул.
- [ ] Бизнес-код не зависит от `pgx`; транзакция не передаётся аргументом репозитория.
- [ ] Изоляция задаётся при `BeginTx`; выбор объяснён в README.
- [ ] Создание и завершение атомарно записывают поездку и историю статусов.
- [ ] `POST /api/v1/trips`: `201`, полная поездка и `Location`; ID и время начала задаёт сервис.
- [ ] Валидация: все обязательные поля, непустые UUID, диапазоны координат, целая неотрицательная цена; неизвестные поля запрещены.
- [ ] `GET /api/v1/trips/{tripId}`: полная поездка либо корректная ошибка.
- [ ] `POST /api/v1/trips/{tripId}/finish`: `active → completed`, время завершения задаёт сервис.
- [ ] Ошибки `400/404/409/500`: `application/problem+json`, правильный `code`, без SQL и внутренних деталей.
- [ ] Поле API `last_position_at` не требует добавления одноимённой колонки до лабораторной № 3.
- [ ] После сбоя записи истории в БД не остаётся частично выполненной операции.
- [ ] 20 конкурентных созданий одному свободному водителю: один `201`, остальные `409 driver_busy`.
- [ ] Два конкурентных завершения: один `200`, один `409 trip_completed`; `finished_at` не перезаписан.
- [ ] README содержит запуск, env-переменные, команды проверок и принятые решения; секретов в Git нет.
