## Обязательная часть: 9 баллов

Шаг 4 означает подготовку целей Makefile. Миграции проверяем после добавления
SQL-файлов; запуск из чистого клона — в конце работы.
Конфигурация проверена на 49 случаях отдельным временным скриптом.
HTTP и жизненный цикл проверены на 11 интеграционных сценариях через временный
TCP-прокси к настоящему PostgreSQL. Сам кластер для имитации сбоев не останавливался.
Миграции проверены в отдельной временной БД: ограничения, границы координат,
20 одновременных вставок, повторный up, два down и повторное применение.
Менеджер транзакций проверен с `-race` на 10 сценариях: выбор исполнителя,
изоляция при другом значении по умолчанию в БД, commit, ошибка, паника, вложенность,
отмена контекста, ошибка commit, таймаут, ошибка BeginTx и 20 конкурентных вызовов.
Репозитории проверены с `-race` в отдельной временной БД: чтение всех полей,
точное распознавание уникального индекса, запись истории, вложенный `Do`, откат
создания и завершения при ошибке истории, конкурентные вызовы, таймаут и отмена.
Пул после проверок закрывается без зависания и занятых соединений.
HTTP-операции проверены через настоящую БД в отдельном окружении проверки:
поля и заголовки ответа, все коды ошибок, 63 некорректных запроса без записей,
границы координат и цены, ошибки истории, 20 конкурентных созданий и два завершения.
HTTP-проверки выполнены и с бинарником, собранным с `-race`. Повторно прошли
11 сценариев здоровья, готовности, стартовых ошибок и остановки по сигналам.
Повторная генерация не меняет файл API; семь файлов контрактов совпадают с курсом.
Из чистого клона прошли запуск окружения, сборка, vet, make test, генерация,
проверка модулей, все три up/down/up, полный API, идемпотентность и make run с Ctrl+C.
Отслеживаемые файлы после генерации и сборки не изменились. Отдельное ревью
не нашло дефектов в рамках лабы 1. Памятка для защиты включена в README.
Идемпотентность проверена через HTTP и PostgreSQL, в том числе с `-race`:
повторы и конфликты, перезапуск, 20 запросов с одним ключом, разные тела и ключи,
ошибки записи истории и ответа, замена просроченного ключа, очистка и конфигурация TTL.
Docker-образ собран на Go 1.24.13: один слой с одним бинарником, 10 506 424 байта.
Контейнер работает от 65532:65532, отвечает на `/ready` с настоящей БД и штатно
выходит по `docker stop`. Проверка Git не нашла реальный URL/пароль БД в истории.
