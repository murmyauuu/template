# TripGo

Сервис поездок для курса «Разработка микросервисов на Go».
Текущая работа — лабораторная № 1: HTTP API и PostgreSQL.

## Состояние

HTTP-сервер запускается с PostgreSQL и отвечает на `/health` и `/ready`.
Конфигурация читается из env, HTTP-типы и интерфейсы сгенерированы из контракта
курса. Миграции и операции с поездками ещё не реализованы: три маршрута поездок
пока используют сгенерированную заглушку и возвращают `501`.

## Требования

- Go 1.24 или новее;
- Docker с запущенным daemon;
- GNU Make;
- `tripgoctl` из [course-infra](https://github.com/course-go-autumn-2026/course-infra).

`tripgoctl` поддерживает Linux и macOS. На Windows команды окружения
выполняются в WSL. Go, Make и CLI должны быть доступны в терминале,
из которого запускается соответствующая команда.

## Окружение первой работы

В корне уже лежит `environment.toml` для лабораторной № 1.
Он включает только PostgreSQL.

В терминале Linux/macOS из корня проекта:

```sh
tripgoctl doctor
tripgoctl cluster start
tripgoctl environment start
tripgoctl connect
```

В WSL этот репозиторий доступен по пути `/mnt/d/template`.
Если CLI установлен в пользовательский каталог, добавьте его в PATH
текущего терминала:

```sh
export PATH="$HOME/.local/bin:$PATH"
cd /mnt/d/template
```

Во время работы оставляйте сеанс Ubuntu открытым: остановка WSL останавливает
его Docker daemon и локальный кластер. Если дистрибутив был остановлен,
после его запуска повторите `tripgoctl cluster start` и
`tripgoctl environment start`.

Адрес PostgreSQL берётся из `.env`, который создаёт `tripgoctl`.
Этот файл, каталог `.tripgo/` и собранные бинарники исключены из Git.
Makefile загружает `.env.example`, затем `.env`: локальные адреса из `tripgoctl`
заменяют значения примера. Настройки можно переопределить при вызове Make,
например `make run HTTP_ADDR=:8081`.

## Конфигурация

Приложение читает только переменные окружения. При прямом запуске бинарника
их нужно передать самостоятельно; файлы `.env` читает Makefile.
Все переменные из `.env.example` обязательны, таймауты должны быть положительными.

| Переменная | Назначение |
|---|---|
| `HTTP_ADDR` | Адрес сервера в формате `host:port` |
| `LOG_LEVEL` | Уровень логов `debug`, `info`, `warn` или `error` |
| `SHUTDOWN_TIMEOUT` | Общий бюджет остановки сервиса |
| `HTTP_READ_TIMEOUT` | Время чтения запроса |
| `HTTP_READ_HEADER_TIMEOUT` | Время чтения заголовков |
| `HTTP_WRITE_TIMEOUT` | Время записи ответа |
| `HTTP_IDLE_TIMEOUT` | Время ожидания следующего запроса на соединении |
| `DATABASE_URL` | URL подключения к PostgreSQL |
| `DATABASE_MAX_CONNS` | Максимальное число соединений, больше нуля |
| `DATABASE_MIN_CONNS` | Минимальное число соединений, от нуля до максимума |
| `DATABASE_MAX_CONN_LIFETIME` | Максимальное время жизни соединения |
| `DATABASE_CONNECT_TIMEOUT` | Таймаут подключения к БД |
| `DATABASE_QUERY_TIMEOUT` | Таймаут запроса к БД |

Продолжительности записываются с единицей измерения, например `5s` или `30m`.
При ошибке конфигурации возвращается имя переменной; пароль из URL в ошибку
не попадает.

## Генерация и сборка

`oapi-codegen` версии `v2.5.1` и `goose` версии `v3.24.1` закреплены в `go.mod`
как Go tools. Отдельная глобальная установка не нужна.

```sh
make generate
go build ./...
go vet ./...
```

В `api/oapi-codegen.yaml` перечислены пять операций первой работы:
`createTrip`, `getTrip`, `finishTrip`, `health`, `ready`.
Результат лежит в `api/trip.gen.go`; этот файл не редактируется вручную.
Исходные файлы в `contracts/` скопированы из курса без изменений.

## Запуск

После `tripgoctl environment start` из корня проекта:

```sh
make run
```

В другом терминале:

```sh
curl -i http://localhost:8080/health
curl -i http://localhost:8080/ready
```

Обе проверки возвращают `200` и `{"status":"ok"}`, когда БД доступна.
`/health` не обращается к PostgreSQL. `/ready` делает `Ping` с бюджетом
`DATABASE_QUERY_TIMEOUT`; при сбое возвращает `503` и `{"status":"unavailable"}`.
После восстановления БД готовность проверяется снова, перезапуск не требуется.

При старте выполняется отдельный `Ping` в пределах `DATABASE_CONNECT_TIMEOUT`.
Если подключение не удалось, сервис завершается с ошибкой до запуска HTTP.
Размер пула, время жизни и таймаут подключения берутся из env.

`SIGINT` (Ctrl+C) и `SIGTERM` запускают остановку: сервер прекращает принимать
соединения, дожидается текущих запросов, затем закрывает пул. На весь процесс
отведён `SHUTDOWN_TIMEOUT`. Если бюджет исчерпан, процесс пишет ошибку в лог
и завершается с ненулевым кодом. Логи выводятся в stdout в формате JSON.

`make build` создаёт бинарник `bin/trip-service`. При его прямом запуске
переменные окружения нужно передать самостоятельно.

Цели `make migrate`, `make migrate-down` и `make migrate-status` подготовлены;
применение миграций станет доступно после добавления SQL-файлов.

## Структура

```text
cmd/trip-service/    точка входа приложения
internal/           код сервиса
api/                сгенерированные HTTP-типы и интерфейсы
contracts/          неизменённые контракты курса
migrations/         SQL-миграции goose
deploy/             файлы контейнерного запуска
docs/               план и проверки
```

Все работы выполняются в одном репозитории. Лабораторная № 1 ведётся
в ветке `homework/01`; PR направляется в `main` и остаётся открытым до проверки.
